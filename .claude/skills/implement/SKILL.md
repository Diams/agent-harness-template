## 入力

確認済みの `docs/specs/<id>/design.md`、または PR の説明欄の内容。レビュー指摘への対応では、その指摘。

## 手順

1. `main` にいる場合は `<type>/<topic>` ブランチを作成する。
2. 作業を小さな単位に分ける。
3. 周辺のコードの書き方に合わせて、単位ごとに実装する。
4. 設計の範囲外の変更が必要になったら、止まって人間に確認する。
5. 意味のある単位で Conventional Commits に沿ってコミットする。

## 成果物

コード。

## 完了条件

設計の範囲をすべて実装した。

`run-tests` に進む。
