# git 運用

GitHub Flow と Conventional Commits を使う。

## ブランチと PR

| 項目 | ルール |
|---|---|
| ブランチ | `main` から `<type>/<topic>` を作成する(例: `feat/password-reset`) |
| 単位 | 1 つの変更につき 1 ブランチ、1 PR。文書とコードを同じ PR に含める |
| マージ | Squash merge。PR タイトルも Conventional Commits にする |
| マージの実行者 | 人間のみ。エージェントはマージしない |
| マージ後 | ブランチを削除する |

## 工程との対応

1. 工程 1 の開始時にブランチを作成する。
2. 工程 1〜3 の文書を順に作成してコミットする。
3. 工程 4、5 を実施してコミットする。
4. PR を作成し、工程 6、7 を実施する。

## コミットメッセージ

```text
<type>(<scope>): <説明>
```

`scope` は任意で、説明は日本語でも英語でもよい。破壊的変更には `feat!: 説明` のように `!` を付ける。

| type | 用途 |
|---|---|
| `feat` | 機能追加 |
| `fix` | バグ修正 |
| `docs` | 文書のみの変更 |
| `refactor` | 動作を変えないコード整理 |
| `test` | テストの追加、修正 |
| `chore` | 雑務、依存関係の更新など |
