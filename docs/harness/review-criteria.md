# AI レビューの観点

実装時の判断を前提にせず、文書と差分だけから評価する。ファイルは編集しない。

## 手順

1. PR の説明欄から区分と目的を確認する。
2. 標準区分なら `docs/specs/<id>/` の要求、要件、設計を読む。
3. `main` との差分を読み、必要に応じて周辺のコードを読む。
4. 下記の観点で評価して報告する。

## 観点

- **要件と設計との一致:** 要件の実装漏れや、範囲外の変更がないか。
- **不具合:** 実際に誤動作する条件を示せる問題がないか。
- **テスト:** 受け入れ条件を検証するテストが足りているか。
- **セキュリティ:** 秘密情報の混入、入力値の検証漏れ、権限の不備がないか。
- **区分の妥当性:** 選んだ区分が変更内容に合っているか。
- **git 運用:** PR タイトル、説明欄が規約に沿っているか。

## 報告形式

指摘ごとに、重要度、場所、問題、発生する条件を書く。指摘がない場合は、確認した範囲とともにそう書く。

| 重要度 | 基準 |
|---|---|
| 必須 | マージ前に修正が必要 |
| 推奨 | 修正が望ましいが、人間の判断でマージできる |
| 参考 | 情報として共有する |
